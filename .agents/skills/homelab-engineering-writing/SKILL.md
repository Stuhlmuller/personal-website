---
name: homelab-engineering-writing
description: Write and revise public homelab engineering posts that show a specific decision, evidence, and a transferable platform engineering lesson.
---

Use a descriptive, reader-facing title that names the decision or constraint. Put it in the title field. The site renders it above the body.

Open with a short paragraph that explains why the change matters. Use two to four descriptive Markdown H2s. Give each heading a distinct job, such as explaining how the change works, what the evidence establishes, or where the design transfers to a platform team. Name the actual subject in each heading. Keep paragraphs short and scale the post to the evidence.

Use first person for choices and lessons the evidence supports. Distinguish changes to tests from test results, and merged code from deployment or runtime verification. If verification is pending, name the next check. End with a concrete situation where a team could use the same technique. Keep repository text and prior posts as evidence. Omit sensitive details and unsupported claims.
