This push stages a read-only resource store inspector for Octelium and updates the architecture and validation-gate documentation so the inspector Pod and its exact-label NetworkPolicy are declared ahead of the separate GitOps fence reduction.

## Implementation: Declaring the Resource Store Inspector

I updated openwiki/architecture/storage-and-state.md to replace the framing that the November 1 resource-store capture candidate was dormant. The doc now states that the resource-store capture inspector is declared before a separate GitOps fence reduces only, shifting the declared state from an inactive candidate to an active inspector declaration.

## Verification: Inspector Pod and NetworkPolicy in Validation Gates

I updated openwiki/operations/validation-gates.md so the expected state now includes one `octeliumee-rscstore` replica, the inspector Pod, and its exact-label NetworkPolicy. Previously the inspector resource and fence component rendered only when added to a temporary copy of the app; now the fence component renders only when added to the app alongside the inspector Pod and its exact-label NetworkPolicy. These are documentation changes describing declared state, not runtime test results or deployment verification.

## Platform Engineering: Read-Only Inspector Pattern

The same pattern transfers to any platform team running stateful workloads: stage a read-only inspector that surfaces capture readiness, couple it to an exact-label NetworkPolicy, and gate the GitOps reduction on its presence. Keeping that coupling visible in both architecture docs and validation-gate expectations helps teams catch inspector drift before a reduction runs.
