I expanded the Harbor mirroring pipeline to include a fixed Home Assistant image scope, enabling reliable mirroring and verification of the Home Assistant Container image in our homelab.

## Scope Expansion in the Harbor Mirroring Workflow

I added `home-assistant` to the options list in `.github/workflows/harbor-mirror.yml` and updated the case statement in the same file so the `IMAGE_SCOPE` variable now accepts the new value. The `harbor-publish.sh` script was also edited to include a new `mirror-home-assistant` case entry that runs the publish command with the tailscale flag.

## Policy and Test Adjustments for Home Assistant

The Rego policy in `policy/workflows.rego` was updated to allow `home-assistant` in the image scope case and to invoke `bash scripts/ci/harbor-publish.sh mirror-home-assistant --tailscale`. Corresponding test files `policy/workflows_test.rego` and `scripts/ci/harbor-publish-test.py` were modified to assert that the new scope is included and to add setup logic that creates and validates a Home Assistant mirror manifest.

## Documentation and Verification Updates

The documentation in `docs/harbor-image-mirroring.md` now describes onboarding for Home Assistant, noting that a fixed inventory selects only the reviewed Home Assistant Container image and uses the same all‑platform copy and authenticated pull verification. The offline static checks in `scripts/ci/offline-static-checks.sh` were adjusted to reflect the expanded scope list.

## Platform Engineering Impact

With Home Assistant explicitly listed as a supported scope, platform teams can now mirror this image reliably without manual scope adjustments. The new manifest handling and verification steps give the same confidence guarantees used for other images, making the pipeline easier to extend and audit across the homelab.
