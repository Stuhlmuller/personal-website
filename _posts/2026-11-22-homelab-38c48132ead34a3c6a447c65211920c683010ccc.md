This push updates the Harbor deployment to include a published Photon security rebuild. The change touches one line in the Harbor Helm values and adds documentation explaining the update. It's a targeted fix that brings our Harbor instance in line with a security patch affecting curl, curl-libs, and expat-libs.

## How the change works

The commit `fix(harbor): deploy the published Photon security update (#2094)` modifies two files. In `clusters/homelab/apps/harbor/values.yaml`, a single line changes within the portal section, selecting the new image tag and digest. In `openwiki/operations/harbor-oci.md`, seven lines are added to document the rebuild, noting that it updated curl, curl-libs, and expat-libs, and that the protected publisher recorded a zero-match runtime audit, a complete authenticated pull, and signature verification for the new image.

## What the evidence establishes

The documentation addition confirms that the new Photon image passed a runtime audit with zero matches, meaning no unexpected binaries or packages were detected. It also confirms an authenticated pull and signature verification, which are the standard checks for any image we deploy from our private registry. The values change is the actual deployment trigger; once reconciled by the GitOps pipeline, the new tag and digest will replace the old one in the running Harbor pods.

## Transfer the security update pattern to the platform team

A platform team maintaining multiple services on a cluster can apply the same technique: when a base image receives a security rebuild, update the corresponding Helm values to point to the new tag and digest, and document the verification steps in the operations wiki. In our homelab, the next check is a runtime confirmation that the Harbor pods have rolled over to the new image and are serving traffic without errors, which the GitOps pipeline should surface in the next reconciliation loop.
