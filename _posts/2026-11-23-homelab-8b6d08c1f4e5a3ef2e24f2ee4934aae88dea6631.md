This push updates the n8n paired checkpoint maintenance, revises storage‑and‑state notes, and refines validation‑gate language to make the fence‑revision and live‑checkpoint receipt explicit for the homelab.

## Stack.hcl valueFiles adjustment

A single line in `IaC/homelab/us-west-2/apps/n8n/stack.hcl` was updated to keep the valueFiles path in sync with the paired checkpoint workflow. The change ensures the declared Deployment renders at zero replicas after the targeted Terragrunt Apply.

## Storage and state documentation refresh

`openwiki/architecture/storage-and-state.md` was revised to describe the logical database dump and n8n PVC backup process. The new text stresses that after the Terragrunt Apply the paired checkpoint must verify that Argo CD synced the exact fence revision, and that the successful live checkpoint receipt records completion of the backup and isolated restore.

## Validation‑gates language update

`openwiki/operations/validation-gates.md` was edited to align the baseline values render one Deployment replica with the overlay that renders zero, noting that no migration Job appears in either render. The checkpoint receipt now explicitly verifies the live backup and isolated restore, removing ambiguity about source rendering alone.

## Platform‑engineering takeaway

Teams running a Kubernetes GitOps homelab can copy this pattern: add explicit fence‑revision checks after a Terragrunt/Helm apply, record a live checkpoint receipt, and update documentation to tie the receipt to backup completion. This makes paired checkpoint maintenance observable, repeatable, and safe across clusters.
