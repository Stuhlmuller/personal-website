This main push implements `feat(adguard): enable dashboard statistics (#2085)`, tightening the validation logic so that the Adguard agent now reports daily statistics and persists them on its retained storage claim. The change corrects a previous configuration where statistics were unintentionally disabled and aligns the expected interval with a one‑day cadence.

## Adding the statistics requirement to the check

In `scripts/adguard-check.py` the old condition demanded that statistics be disabled while recent query visibility was enabled. The patch replaces that with two separate requirements: first, that recent query visibility (`querylog.enabled`) is true, and second, that statistics are enabled and use an interval of 86 400 000 seconds (one day). This makes the agent publish daily stats instead of discarding them.

## Updating CI tests and runtime assertions

Test files such as `scripts/ci/adguard-check-test.py` and `scripts/ci/adguard-runtime-test.py` were adjusted to expect `{'enabled': True, 'interval': 86400000}` for the third entry and to assert that `num_dns_queries` meets or exceeds the size‑memory claim plus a small buffer. Runtime tests now verify that the reported query count satisfies the newly defined threshold, closing the gap between the check logic and observed behaviour.

## Extending the guardrail to other services

The same policy—requiring enabled statistics with a daily interval—has already been applied to the inventory manifest and the adguard workflow. Future workloads can adopt the pattern by editing their local check scripts and CI tests accordingly, keeping the guardrail explicit rather than relying on hidden comments.
