I merged a persistent Home Assistant container deployment and updated related documentation and Harbor chart configurations to clarify state handling, onboarding steps, and image versioning.

## Home Assistant Persistent Deployment

I added a persistent Home Assistant container deployment in the GitOps repository, ensuring the service retains its local claim on `zimaboard-0` for configuration, credentials, and the SQLite recorder. The documented backup and recovery path now specifies that archives are downloaded and stored off the node, giving operators a clear migration path.

## Argo CD Onboarding Clarifications

I updated `docs/argocd-app-onboarding.md` with a concise addition about cross‑namespace RoleBindings, clarifying how RBAC interactions affect the onboarding workflow and preventing ambiguity for new users.

## Harbor Image Chart Configuration

I extended `scripts/config/harbor-image-charts.json` with a new chart entry using the `app-template` chart and `targetRevision` set to `4.4.0`, aligning the repository’s image versioning with the latest stable release and enabling consistent chart-based deployments.

## Storage and State Documentation

I added a dedicated section to `openwiki/architecture/storage-and-state.md` describing Home Assistant’s retained local claim and backup strategy, and updated `openwiki/workloads/inventory.md` to note that source declarations alone do not prove a rollout, reinforcing verification practices across workloads.
