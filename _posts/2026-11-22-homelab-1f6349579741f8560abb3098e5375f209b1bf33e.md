This push adds documentation for a one-time cleanup of a retained Compass pod that was holding an old upstream image in the Argo CD image summary. The note records the exact matching criteria and verification steps so the cleanup can be reproduced or audited later.

## Record the Compass pod cleanup workflow

I added a new section to the Compass application notes that describes how Argo CD includes retained terminal pods in the Application image summary and how a post-sync hook removes the historical pod. The procedure requires matching the pod's finished phase, ReplicaSet, and old image before sending a delete request that checks the UID and resource version returned by Kubernetes. This documentation turns a one-time fix into a repeatable runbook.

## Establish what the evidence shows

The commit message identifies the change as a fix for cleaning up the retained upstream-image pod, and the patch adds the explanatory section to the workload documentation. The actual cleanup script or hook is among the withheld files, so the merged evidence is the documentation itself. The note makes no claim about test results; it only records the intended behavior and the verification sequence.

## Transfer the pattern to platform teams

A platform team operating Argo CD with similar image drift issues can adopt the same documentation-first approach. Write down the matching criteria, the delete request safeguards, and the post-cleanup verification before running the one-time hook. In our homelab the next check is to confirm the cleanup script exists and that the pod is actually absent after the hook runs, but the documented procedure is now the source of truth.
