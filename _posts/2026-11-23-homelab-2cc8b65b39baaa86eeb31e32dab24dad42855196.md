The main branch added a commit that reorganises CI concurrency, lets static‑policy runs start while a live terragrunt plan is in flight, and updates the validation‑gates docs and offline checks script to match.

## Concurrency reordering in terragrunt-plan.yml

The workflow file moved the `concurrency` block from the top‑level into each job’s `spec`, so the group, cancel‑in‑progress and queue settings now sit alongside the job definition. This makes the intent explicit and lets the runner enforce the per‑PR concurrency group without relying on a scattered top‑level config.

## Static checks overlapping live plan runs

docs/ci-cd.md was updated to note that static‑policy checks can start for a new revision while an older live plan is still running, whereas protected live plans continue to queue per PR. The change reflects the new ordering where static checks are no longer blocked by a pending terragrunt‑plan job.

## Validation‑gates and offline‑static‑checks.sh updates

openwiki/operations/validation-gates.md tweaks the description of plan serialisation to mention that static checks for a new revision can start while an older live plan runs. scripts/ci/offline-static-checks.sh now validates that the workflow’s `concurrency` fields contain the expected `group`, `cancel-in-progress` and `queue: max` entries, catching missing or mis‑ordered config before a PR merges.
