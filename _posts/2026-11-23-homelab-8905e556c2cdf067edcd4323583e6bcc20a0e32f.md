I added support for Immich runtime images to the Harbor mirroring pipeline, enabling the server, PostgreSQL, and Valkey components to be published as part of the same automated process.

## Immich Image Scope Integration

I extended the workflow options in `.github/workflows/harbor-mirror.yml` to include `immich`, updated the case statement to recognize the new scope, and modified `scripts/ci/harbor-publish.sh` to accept a `--tailscale` flag for Immich. A new JSON file `scripts/config/harbor-immich-images.json` defines the image list for Immich, and the workflow now calls `scripts/ci/harbor-publish.sh mirror-immich --tailscale` for that scope.

## Policy, Test, and Verification Adjustments

I edited `policy/workflows.rego` to add a case for `immich` that runs the same publish command, and updated `scripts/ci/harbor-publish-test.py` to assert that `immich` appears in the allowed workflow list. The test changes are to the test harness, not to the runtime result, so the next verification step is to execute a real mirror job that includes Immich and confirm the publish step completes and the recorded failure phase is correctly reported.

## Documentation, Next Check, and Team Reuse

The README now documents the new `image_scope=immich` option and how to use the tailscale flag. I will next run a full Harbor mirror with Immich enabled, verify that the publish succeeds, and check that any failure is labeled with the appropriate phase. This pattern can be copied by other homelabs that need to publish multiple runtime images through a single, auditable CI job.
