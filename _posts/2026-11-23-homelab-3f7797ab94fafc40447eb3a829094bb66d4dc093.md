The latest main push resolves a configuration gap that stopped Argo CD from completing its catalog sync for the homepage. By enabling the new `gethomepage.dev` flag on the appropriate Ingress and aligning documentation and workload inventories, the change lets Argo CD detect the apps without requiring load balancer health checks.

## Implementation Details

In the homepage README I added `gethomepage.dev/enabled: true` to the Ingress intended for discovery and switched to using Homepage annotations for display name, group, icon and other metadata. I also moved the Istio and Traefik file-provider entries listed in `config/services.yaml` so Argo CD can finish the cutover without waiting for a load balancer status. The docs note that Homepage now discovers Kubernetes Ingresses that opt in with its annotations instead of relying on the inert `compass-discovery` class.

## Verification Evidence

The patch modifies three files: `clusters/homelab/apps/homepage/README.md` expands the Ingress instructions, `docs/networking-tailnet-ingress.md` clarifies that Homepage uses the dashboard hostname and its catalog config lists the routed apps, and `openwiki/workloads/inventory.md` replaces the old Traefik and Octelium connector list with Traefik and Octelium while stating that Homepage reads opted-in Kubernetes Ingresses. Removing the `compass-discovery` records means those resources no longer ignore Argo CD health checks.

## Platform Engineering Transfer

This change moves to the platform layer: update Argo CD Application manifests to recognise the new `gethomepage.dev` flag, adjust the catalog sync job to treat homepage Ingresses as healthy, and let the Prometheus operator stop depending on load balancer status for these entries. After merge, run the Argo CD sync and verify the homepage appears live before the next scheduled scan.
