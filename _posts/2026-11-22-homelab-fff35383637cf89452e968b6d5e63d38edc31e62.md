I added cert-manager v1.20.5 to the Harbor image catalog and documented the security verification, keeping v1.20.3 digests as a rollback path while staging the patched release for production.

## Add five v1.20.5 component images to harbor-images.json

The `scripts/config/harbor-images.json` catalog grew by fifteen lines covering the controller, CA injector, webhook, ACME solver, and startup API check images for both linux/amd64 and linux/arm64. Each entry records the exact digest so the GitOps pipeline can pin the same artifact across environments.

## Document the security prerequisite in harbor-oci.md

I added a new section to `openwiki/operations/harbor-oci.md` explaining why v1.20.5 was chosen over v1.21.3. Anonymous Trivy scans against the November 22, 2026 database found zero fixable HIGH or CRITICAL findings for v1.20.5, while the newer v1.21.3 still carries fixable findings. The note also records that the five v1.20.3 rollback digests remain in the catalog.

## Verification pending

The catalog update and documentation are merged, but the end-to-end flow has not run in CI yet. The next check is to publish the five v1.20.5 indexes using the existing Harbor mirror scope, run authenticated pulls, then update the Argo chart, chart inventory, and the five runtime digests together. After that I will verify the exact GitOps revision, webhook readiness, and non-production certificate issuance and renewal.

## Pattern for secure image promotion

This workflow—scan candidate images, retain the previous version as rollback, stage the clean release in the catalog, document the finding, then promote in a single atomic PR—can be reused for any operator upgrade. The key is keeping the catalog as the source of truth and gating promotion on a clean vulnerability database result.
