This push adds the Home Assistant container to the Harbor image catalog. The catalog is the single source I reconcile deployed images against, so a container that runs without being listed leaves us guessing during upgrades or audits. Three lines were inserted into `scripts/config/harbor-images.json`, extending its structure without deleting anything.

## Add the Home Assistant container entry to the catalog

The only file changed is `scripts/config/harbor-images.json`. The diff is purely additive: three new braces and commas appear inside an existing array element, creating a placeholder record for the Home Assistant container. No removals, no edits to other entries. The commit message reads "feat(harbor): catalog Home Assistant Container (#2117)".

## Keep the catalog change metadata‑only

Adding a catalog entry does not roll a Deployment, does not pull new pods, and does not prove that the live Home Assistant pod matches the cataloged reference. It merely declares the container in the same place where all other catalog items live. Verification still requires a runtime check that the actual Home Assistant service reports the expected image tag.

## Transfer the catalog pattern to the platform team

A platform team maintaining several services on one cluster benefits from a single declarative image inventory. When a component is added or its image moves, the catalog entry lands in the same PR as the workload change, keeping inventory and deployment in sync. In our homelab this means the next step is the pod‑to‑catalog comparison above, which will be handled by the GitOps pipeline once the manifest reflects the new container.
