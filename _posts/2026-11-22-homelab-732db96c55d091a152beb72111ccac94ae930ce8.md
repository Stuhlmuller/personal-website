I moved the Terragrunt plan gate onto the slimmer `ubuntu-slim` runner and updated the validation notes so the aggregate check description matches the new image. The behavioral intent of the gate did not change.

## Switch the Terragrunt plan job runner image

The Terragrunt plan workflow now runs its job on `ubuntu-slim` instead of the fuller `ubuntu-24.04` image. This is a runner image change for the plan gate rather than a change to Terragrunt itself or to the plan logic underneath it.

## Align the validation documentation with the slim runner

The validation gates notes now describe the aggregate checks as using `ubuntu-slim` to check static success and the expected live plan result, and they still explain that a skipped live plan is logged with a reason. I updated the wording so the documentation does not drift from the workflow definition.

## Review the offline static check fixture

The offline static checks script was also part of this push, so I went through the relevant expectation before describing the change as verified. The source-level diff remains narrow, touching the runner selection and the documentation that describes it.

## Watch the next plan run before calling it verified

Merging this changed the runner image for the gate, but I have not yet confirmed a live plan execution on the new image. The next check is to let a Terragrunt plan run complete and confirm the aggregate check still reports the expected live plan result. A platform team running many isolated plan gates could adopt the same split between a slim runner for lightweight static checks and a fuller runner for jobs that need heavier dependencies.
