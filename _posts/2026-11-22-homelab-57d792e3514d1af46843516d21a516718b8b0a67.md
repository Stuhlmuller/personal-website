This main push trims unnecessary checks in the `scripts/ci/harbor-publish-test.py` helper so that simulated `sleep` calls no longer require an extra Python interpreter launch during startup. The change lowers the overhead when the harbor publishing pipeline runs its retry logic and makes the test suite faster at bootstrap.

## Implementation details

In `scripts/ci/harbor-publish-test.py` the previous code asserted that the first argument to the `sleep` command was a numeric string. The patch removes that assertion and replaces the generic command loop with a dedicated branch that uses `self.executable("sleep", ...)`. It also adds a small logging step that writes a JSON record to `self.calls`. By handling `sleep` explicitly instead of launching a Python interpreter for every simulated wait, the helper starts quicker.

## Test adjustments

The matching test file `scripts/ci/harbor-publish-test.py` was trimmed: the old `elif command == "sleep"` block and the full `for` list were collapsed into a `case` statement that treats non‑digit arguments by exiting with status 96 and emits the appropriate JSON entry. Runtime assertions were updated to expect the reduced number of calls, confirming that the new path still captures delays without heavyweight process creation.

## Applying the pattern elsewhere

Other CI scripts that simulate short waits (such as `timeout`, `skopeo`, or `regctl`) can follow the same approach: replace broad command enumerations with targeted executable calls and avoid spawning interpreters for brief pauses. This keeps the startup phase lean while preserving accurate delay recording.
