I replaced the loose `CHART_KINDS` set in `scripts/crossplane-retirement-check.py` with an exact `CHART_RESOURCES` inventory for the `Crossplane` 2.3.3 chart rendered from the app stack. The companion change to `openwiki/workloads/inventory.md` documents the 23 tracked chart identities so the pre-prune retirement check can verify namespace-qualified names instead of kinds alone.

## Crossplane retirement check now matches exact chart resources

In `scripts/crossplane-retirement-check.py` the old `CHART_KINDS` set grouped only API version and kind. I replaced it with `CHART_RESOURCES`, which records tuples including namespace and resource name for Secrets such as `crossplane-root-ca`, `crossplane-tls-client`, and `crossplane-tls-server`; Services such as `crossplane-webhooks`; ServiceAccounts and Deployments for `crossplane` and `crossplane-rbac-manager`; and ClusterRoles including the aggregate-to-admin, browse, edit, and view entries. This lets the script confirm the precise surface rendered by the chart before allowing chart pruning.

## Inventory documentation reflects exact tracked identities

In `openwiki/workloads/inventory.md` the pre-prune description now names the exact 23 tracked chart identities alongside the pinned 21 core CRDs. It keeps the requirement for zero active workloads and volume claims and lists only three unchanged initializer objects: the default `DeploymentRuntimeConfig`, the empty package `Lock`, and the default `ManagedResourceActivationPolicy`. The wording shifts from `homelab API` to `direct homelab API` to clarify where the check runs.

## Verification pending against staged cluster

This is a merged code and documentation change; it is not itself a runtime verification result. I have not yet run the retirement script against a cluster. The next check should execute `scripts/crossplane-retirement-check.py` against a staging cluster and confirm that the exact resource list matches the rendered `Crossplane` chart and that the three initializer objects remain unchanged before any production prune.

## Exact-inventory pattern for chart retirement

A platform team can reuse this pattern when retiring any Helm-managed chart. Capture namespace-qualified names from the rendered release rather than checking kinds only, and fail the pre-removal gate if an expected object is missing or an unexpected object appears. The same approach fits `cert-manager`, `ingress-nginx`, or other operator charts where safe removal depends on a known surface area.
